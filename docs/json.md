# JSON view

`project.ToJSON()` / `project.MarshalJSON()` / `project.WriteJSON(w)` — see
[project.md](project.md) for the method reference.

## Description

`Project` provides a set of snake_case JSON mirror types (`JSON*`) for exporting
to external consumers (a front-end inspector, CI reports, diff tools).

> ⚠️ **One-way**: there is no `ReadJSON`. The JSON view does not retain the
> underlying RIFX bytes, so a writable `Project` cannot be rebuilt from JSON.
> **Any modification must go through the binary path** (`Open` → `Set*` →
> `WriteAEP`).

## Example

```go
// standard encoding/json interface
b, _ := json.MarshalIndent(proj, "", "  ")
os.Stdout.Write(b)

// write straight to a writer
proj.WriteJSON(os.Stdout)

// or take the intermediate struct and handle it yourself
jp := proj.ToJSON()
fmt.Println(len(jp.Compositions), "comps in JSON view")
```

## Naming & encoding conventions

- All fields are snake_case (`frame_rate`, `work_area_start_seconds`, `is_box_text`).
- Time values carry a `_seconds` suffix.
- Colors are `#RRGGBB` strings (`Composition.BGColor` / `Mask.Color`).
- Floats are mostly rounded to 3–4 decimals (kills float noise, eases diffing).
- Defaults (boolean `false`, empty slices) are dropped via `omitempty`.

## Relationship to `Project.WriteAEP`

| Task | Path |
|---|---|
| Read-only inspection / reporting | `WriteJSON` |
| Modify and save | `Open` → `Set*` → `WriteAEP` |
| Rebuild .aep from JSON | ❌ not supported |

If you need to drive .aep generation from external data, the current route is:

1. Prepare a template .aep manually in AE.
2. `Open` the template with this library.
3. Apply external data via `SetPath` / `SetStaticValue` / `SetTime` / `SetValue` / `SetText`.
4. `WriteAEP` to a new file.

The length-preserving constraint means external data can only drive value
changes on existing keyframes, equal-byte text replacement, and the like — it
can't add or remove structure.
