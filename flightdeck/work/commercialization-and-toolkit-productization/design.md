# 设计 — 商业化与 Toolkit 产品化

## 总目标

把“能够解析和生成 AEP 的代码库”发展为可被真实生产流程采用的 Headless AEP Toolkit：无需启动 After Effects，即可安全地理解、检查、比较、迁移和治理 AEP，并形成可持续的开源采用或商业收入。

核心价值不是出售 parser，而是减少人工打开 AE 检查工程、判断依赖、定位变化和执行迁移的成本。

## 产品承诺

给定一个 AEP，工具应能在明确的资源边界内回答：

- 工程包含什么；
- 依赖哪些素材、字体、插件和版本能力；
- 是否适合目标环境；
- 两个版本发生了什么变化；
- 哪些迁移可以自动执行，哪些必须人工确认；
- 输出结论由哪一级测试或 AE 证据支持。

## 商业边界

开放核心建议保留 parser、稳定 profile、基础 diff、统一 CLI 和安全 round-trip。商业价值优先来自托管运行、批量队列、资产目录、权限审计、策略治理、私有连接器、企业部署、长期支持和迁移服务。

本设计不锁死开放核心模式。若真实客户更适合私有授权或完全托管，应由验证结果决定，而不是把开源当作目标本身。

## 约束

- 暂不执行市场推广、外部联络、发布或收费实验。
- 不以增加更多 AE 字段代替用户价值验证。
- 不在综合代码升级 P0/P1 未收敛时扩大稳定性承诺。
- 任何商业 surface 必须建立在同一个核心 module interface 上，不能复制 parser/migration 逻辑形成分叉。
