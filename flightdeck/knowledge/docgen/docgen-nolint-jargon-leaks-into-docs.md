# ⚠ //nolint:jargon on exported doc comments leaks into docgen public docs

SUMMARY: //nolint:jargon on exported doc comments leaks into docgen public docs
READ WHEN: 给导出符号 doc comment 加 //nolint:jargon 压制 jargon 前;TestDocsUpToDate 报 docs stale 且 docs 里出现 nolint:jargon / 内部 codename;docgen 公开文档泄漏内部术语(py-aep 等);设计任何注释 jargon linter + 抑制机制时

---

## Signature
- symptom: `TestDocsUpToDate` fails (`property.md is stale — run go generate ./cmd/docgen`); generated `docs/*.md` + `docs_index.json` contain the literal `//nolint:jargon` directive AND the codename it was meant to hide (e.g. `... mirrors py-aep's `comp.time_scale` //nolint:jargon naming ...`)
- error_type: —
- where: cmd/docgen rendering of exported-symbol doc comments (internal/scene exported accessors → docs/*.md)
- trigger: append `//nolint:jargon` to an EXPORTED-symbol doc comment to silence the comment jargon linter, then regenerate docs

## Symptom / repro

The comment jargon linter (`go run ./cmd/capindex --lint-comments`) flags internal
codenames (py-aep, V2.2, …) in comments and SKIPS any line containing the substring
`//nolint:jargon`. A bulk cleanup pass suppressed py-aep in a batch of exported `scene.Layer` /
`scene.Composition` / `scene.Property` accessor doc comments by appending a trailing
` //nolint:jargon`. Lint went green. But `docs/*.md` are generated by docgen FROM those
same doc comments, so after `go run ./cmd/docgen -manifest docs/docgen.json`:

- `TestDocsUpToDate` fails (committed docs no longer match generated output), and
- the generated `composition.md` / `constants.md` / `footage.md` / `layer.md` /
  `project.md` / `property.md` / `docs_index.json` now render the directive verbatim, e.g.
  `NumLayers returns ... provided for py-aep API parity. //nolint:jargon` — both the
  internal codename AND the `//nolint:jargon` tooling directive leak into the public API docs.

~30 exported accessors leaked this way in one regen.

## Root cause

docgen renders the doc-comment text **verbatim**. The jargon-lint suppression mechanism
(`//nolint:jargon` substring) lives in the comment text, so on a doc-feeding (exported)
comment it (a) does NOT remove the offending jargon — only hides it from the linter — and
(b) adds a tooling directive that is itself meaningless to a doc reader. Both ride into the
rendered docs. `nolint` is the wrong tool for the documentation source: it suppresses the
*alarm*, not the *cause*.

## Fix

**Jargon in an EXPORTED-symbol doc comment (the docgen documentation source) must be
REWRITTEN out, never `//nolint:jargon`-suppressed.** Reserve the nolint escape for comments
docgen never renders: function-body comments, file-header banners, and methods on
unexported types (e.g. `serializer.layerBackrefs.*`). Rewrite the prose in the library's own
neutral voice (drop "mirrors py-aep's X" → describe behavior / cite AE's own object model).

Guards (all should hold after any comment-jargon change):
- `go test ./cmd/docgen/` — `TestDocsUpToDate` green (catches the staleness).
- `grep -rn "nolint:jargon" docs/` == 0  AND  `grep -rni "py-aep" docs/` == 0 (no leak).
- Regenerate docs (`go run ./cmd/docgen -manifest docs/docgen.json`) as part of the SAME
  commit that changes any doc comment, so docs never lag.

Heuristic for "exported / doc-feeding": capitalized name on an EXPORTED type reachable from
the `internal/aep` facade. A capitalized method on an unexported type is NOT doc-feeding
(capitalization there is forced by an interface signature) — nolint is fine there.

Related: [[docgen-alias-blindspot-false-green]] (a different docgen false-green — alias
blindspot drops doc sections; this one leaks directives into rendered docs).

## Cases
- 2026-06-21 first seen — a bulk py-aep cleanup pass nolint'd ~30 exported scene/ accessor
  doc comments; regen leaked `//nolint:jargon` + py-aep into 6 docs/*.md + docs_index.json;
  `TestDocsUpToDate` caught it. Fixed: rewrote the exported doc comments in neutral voice
  (commit ed9dbbc), then removed py-aep from all remaining non-test comments (commit
  c0964d6). End state: docs carry zero py-aep and zero nolint:jargon.
