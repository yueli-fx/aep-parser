# 子代理协作

只有在当前运行环境允许、任务边界清晰且可以独立并行时才派发子代理；主会话始终负责整合结果并维护权威的 Flightdeck Work 文档。

## 适合派发的工作

- 多文件只读审查、互不依赖的检索或不同角度的分析。
- 输入、输出、验证方法和允许修改的路径都能一次说明清楚的子任务。
- 子任务完成后可以由主会话独立复核和合并的工作。

相互依赖的实现步骤、需要持续产品判断的工作，或会同时修改同一组文件的任务通常留在主会话执行。

## Brief 必备内容

每个派发任务应明确：

1. 单一、可验证的目标和明确的非目标。
2. 可读取或修改的路径，以及必须保留的现有改动。
3. 与任务直接相关的项目约束、接口契约和知识链接。
4. 预期输出格式与验证命令。
5. 是否允许写文件；未授权时保持只读。

不要假设子代理自动继承对话、技能或已读取的项目知识；实际继承能力由当前代理机制决定。即使上下文会继承，也应让 brief 自足到足以审查任务边界。

## 整合规则

- 主会话检查子代理的证据和工作区实际状态，不直接把结论当作事实。
- 子代理输出属于当前 Work 时，主会话把必要结果收敛进 `index.md`、`context.md`、`plan.md`、当前 Slice 或 Work 的 `references/`。
- 不建立跨会话锁、认领协议、独立完成台账或第二套工作流图。
- 多个代理并行时避免重叠写入；发生冲突时由主会话依据仓库真相统一处理。
